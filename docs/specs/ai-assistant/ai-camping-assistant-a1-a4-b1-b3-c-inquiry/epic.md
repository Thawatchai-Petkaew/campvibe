# AI Camping Assistant (A1-A4, B1-B3, C·Inquiry) (CAM-266)

## Why
A conversational assistant answers any camping question from live platform-internal data, renders results as clickable cards in chat, and hands the camper onward — proving that tool-use over the normalized schema (ADR-009) answers correctly before investing in the heavier inquiry/handoff path. **KPI:** not measured (POC — first validate answer correctness + that spend stays contained under the guardrails).

## Scope
- In: the M2 chat foundation over live data — a read-only tool layer + OpenRouter client (CAM-270), a single-turn chat endpoint (CAM-271), and a Discover-only chat UI (CAM-272). Availability is always a live query; the model never touches the DB directly.
- Out: HostLead / inquiry handoff (needs the HostOS lead inbox, M1.2, ADR-011) → later; embeddings / semantic "vibe" search → deferred (ADR-009, content-only); Compare/Decide (B) + Plan/Trip (D) clusters → R2/R3.

## POC arc (3 stories, Discover-only)
- **CAM-270 — Foundation (this):** read-only tool layer (`searchCampsites` + `checkAvailability`) + a server-only single-round OpenRouter client + additive petFriendly filter. Lib-only, no UI. Spend is owner-gated at G2 (self-skip when the key is unset).
- **CAM-271 — Chat endpoint:** single-turn orchestration over the tool layer (sanitize → model → validate tool call → execute → structured result), per-IP rate-limit + spend cap; returns `{ answer, cards }`.
- **CAM-272 — Chat UI:** a floating chat entry + a home entry, Discover-only; in-chat cards link to `/campgrounds/[slug]` (no HostLead handoff in the POC).
- Note: C·Inquiry (HostLead handoff, ADR-011) is deferred until the HostOS lead inbox (M1.2) exists — the POC ends the funnel at the campground page.
