# Assistant answers real camper asks (gap closure W1) (CAM-456)

## Why
The gap between what campers actually type and what the assistant can answer is not an NLU problem — the model already turns "by the way" Thai utterances ("มือใหม่หัดกาง", "หนีเมืองไปฮีลใจ") into intent. The intent has nowhere to land: `searchCampsites` accepts only province/price/taxonomy/petFriendly, there is no conversation state, no derived facets, no code-side date resolver, and — most dangerous — no eval harness, so every prompt/tool change today is a guess (gap-closure research §2, §6). This epic builds the semantic data layer's first wave so intent has a place to land, and puts a golden suite under it so every later change is measured, not guessed.

**KPI:** eval pass-rate on the 40-case golden tool-call suite (tool-called + parameters correct ≥95%, guardrail 100%, no zone-B hallucination). Baseline: not measured — story 1 establishes it and replaces the estimates in research §2.

## Scope
**In — wave 1, exactly these 9 stories, in this order:**
1. Eval harness — 40 golden tool-call cases gate every assistant change, including zone assertions (general-knowledge answers must NOT call tools); establishes the baseline report.
2. Assistant finds camps in all 77 provinces — complete Thai province resolution; today only ~12 are seeded, so out-of-list provinces are understood but never found (a silent bug live today).
3. Answer policy 3 zones — general camping questions answered without tool calls, always bridging back to real data; camp-specific facts stay tool-only; transactional stays human-confirm.
4. Assistant remembers shown results — conversation state (`last_results`/`shown_ids`/`focus`/`party`) injected per turn instead of replaying the last 10 messages only.
5. Follow-up search — `excludeIds`, `sort`, OR-within-facet-group, batch `getCampDetails` + `compareCamps`.
6. Thai dates resolve in code — deterministic `resolveDates` tool returning a date-set + a `ThaiHoliday` table (move date logic out of the prompt).
7. Search by region — a six-region rollup derived from provinces.
8. Derived facet scores — family/beginner/road-access computed from existing fields (rules-only, no review mining yet).
9. Bulk availability — one ask checks many camps × dates, hard-capped before the loop runs (CAM-344 lesson).

**Out — phase 2 (data acquisition), backlog candidates, trigger "after wave-1 eval baseline proves value":**
- Review aspect mining · camp condition pixels · `RegionSeasonProfile` · policy tiers (cancellation/fee) · lexicon / `ConceptMapping` (KG-lite) · party model (adults/children/pets/vehicles).

**Out — phase 3 (new capability), same trigger:**
- User memory · watchers · gear KB · trip entity.

**Out — rejected in the research (not deferred, decided against):**
- Knowledge Graph engine / graph DB / GraphRAG — entity shape is a shallow 2–3-hop star with a stable ontology; Postgres mapping tables ("KG-lite") cover the whole corpus (research §3).
- LangChain / LangGraph migration or wholesale repo copy — the hand-rolled bounded loop is the same core, tighter, and already through security review; ~95% of the framework is dead weight for 1 provider / 7 tools / 1 domain (research §4.1). Pattern-study only (StateGraph / Checkpointer / Interrupt), no port.

## Story arc
Ticket ids pending (ticket API 401 at intake, 2026-07-20).
1. Baseline is measurable — golden suite runs the real agent loop and reports how much of the corpus lands today.
2. A province name anywhere in Thailand resolves to a real search result.
3. A general camping question gets a straight answer with no tool call, then a bridge back to live data.
4. "เอาอันที่สอง" works — the assistant knows what it just showed.
5. Follow-ups refine instead of restart — exclude seen, sort, OR-facets, compare in one turn.
6. "วีคเอนด์เว้นวีคเดือนนี้" resolves to exact dates in code, not by prompt guesswork.
7. "ภาคเหนือ" searches every northern province via the region rollup.
8. "เหมาะครอบครัว / มือใหม่ / รถเข้าถึง" is a rankable score derived from fields we already store.
9. "ว่างไหมช่วงนี้บ้าง" checks many camps at once within a hard cap.
