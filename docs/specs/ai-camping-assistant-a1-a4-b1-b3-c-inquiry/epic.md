# AI Camping Assistant (A1-A4, B1-B3, C·Inquiry) (CAM-266)

> Note: this mirrors the canonical epic artifact at `docs/specs/ai-assistant/ai-camping-assistant-a1-a4-b1-b3-c-inquiry/epic.md`. The current `ticket-sync` path resolution places CAM-410 here because its ticket carries no `featureName`; the sibling stories live under `docs/specs/ai-assistant/`. Consolidation flagged to the orchestrator.

## Why
A conversational assistant answers any camping question from live platform-internal data, renders results as clickable cards in chat, and hands the camper onward — proving that tool-use over the normalized schema (ADR-009) answers correctly before investing in the heavier inquiry/handoff path. **KPI:** not measured (POC — first validate answer correctness + that spend stays contained under the guardrails).

## Scope
- In: the M2 chat foundation over live data — a read-only tool layer + OpenRouter client (CAM-270), a single-turn chat endpoint (CAM-271), a Discover-only chat UI (CAM-272), and Wave-1 conversational polish (CAM-404..410). Availability is always a live query; the model never touches the DB directly.
- Out: HostLead / inquiry handoff (needs the HostOS lead inbox, M1.2, ADR-011) → later; embeddings / semantic "vibe" search → deferred (ADR-009, content-only); Compare/Decide (B) + Plan/Trip (D) clusters → R2/R3.

## POC arc + Wave-1 polish
- **CAM-270 — Foundation:** read-only tool layer (`searchCampsites` + `checkAvailability`) + a server-only single-round OpenRouter client. Lib-only. Spend owner-gated at G2 (self-skip when the key is unset).
- **CAM-271 — Chat endpoint:** single-turn orchestration (sanitize → model → validate tool call → execute → structured result), per-IP rate-limit + spend cap; returns `{ answer, cards }`.
- **CAM-272 — Chat UI:** floating + home chat entry, Discover-only; in-chat cards link to `/campgrounds/[slug]`.
- **CAM-404..409 — Wave-1:** province-name resolution, plain-text answers, panel sizing, terrain/relative-date understanding, abort resilience.
- **CAM-410 — Follow-up chips (this):** the chat response extends by addition to `{ answer, cards, suggestions }` — 0–3 sanitized Thai follow-up questions the camper can tap next, generated in the SAME single completion (no second paid call) and rendered as chips reusing the welcome-pill visual + send path.
- Note: C·Inquiry (HostLead handoff, ADR-011) is deferred until the HostOS lead inbox (M1.2) exists.
