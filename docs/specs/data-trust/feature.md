# Data & Trust

## Overview
The data-correctness and host-trust backbone of CampVibe: availability that reflects real inventory, atomic/AI-ready records, and host-operational data (blocks, capacity, holds) that a host can rely on when money and dates are at stake. Serves the **Host** persona operating a camp. ↑ Master-Plan: `docs/project/master-plan.md` · product-plan item: availability correctness (ว่างจริง) + HostOS core.

## Architecture overview
- Entities: `CampSite`, `Spot`, `Booking` (confirmed/pending), `BlockedDate` (host closures), and `InternalHold` (temporary negotiation holds, CAM-302) — all linked by ID and summed by one shared calculation.
- API surface: `GET /api/campsites/[id]/availability` (calendar), `GET /api/campsites/[id]/remaining-capacity`, host `blocked-dates` CRUD, and the CAM-302 host hold service (create · list · release). `lib/campsite-availability.ts` is the single source every consumer reads.
- ADRs: `docs/adr/ADR-012-hostos-data-model.md` (§4 InternalHold) · `ADR-006` (serializable inventory lock) · `ADR-005` (booking snapshot / exclusive-checkout dates) · `ADR-009` (no forked/duplicated data path). schema: `prisma/schema.prisma`.

## Design overview
Host-facing availability views (the CAM-55 month calendar, the CAM-56 availability page) reuse `components/ui/*` primitives and `DESIGN.md` tokens. Loading/empty/error/blocked states follow `.claude/rules/loading.md`. No new UI ships in CAM-302 (API + math core).

## Appetite
Per-story: G1 (scope) + G2 (design) owner review-rounds; model-spend kept lean. Blowing the appetite means re-scoping down (as CAM-302 did by cutting the hold UI to a follow-up), not extending the clock.

## No-gos
- No scheduled-job / cron infrastructure for expiry (lazy read-time expiry only, ADR-012 §4).
- No parallel availability calculation — every consumer reads `lib/campsite-availability.ts`.
- No payment/gateway custody in this feature (host handles money; platform is a ledger/workflow layer, ADR-012).
- No public/guest-facing hold surfaces.

## Live status
Rollup lives on `/status` + `docs/specs/INDEX.md` (generated by `node scripts/ticket-sync.mjs index`) — not hand-maintained here.

## Key decisions
- One availability source (`lib/campsite-availability.ts`) — CAM-190/CAM-267 paid for two "forgot a source" bugs; holds must integrate here, not fork (ADR-009 / ADR-012 §4).
- Lazy hold expiry over cron (ADR-012 §4) — no new operational surface for a solo, pre-launch project.
- `InternalHold` ships as a reduced additive slice in CAM-302; the lead/quote/booking FKs land later (CAM-311).
