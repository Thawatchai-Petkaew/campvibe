# Tech — Stop showing a Thai camper the raw word PAID (CAM-618)

## Data model
No new entity/field, no migration. `prisma/schema.prisma`'s `BookingStatus` enum (`PENDING`, `CONFIRMED`, `PAID`, `CANCELLED`, `COMPLETED`) is unchanged — it has been correct since CAM-98 (`feat(schema): S1 — string fields → Prisma enums`, 2026-06-21, commit `0449b62`, which introduced the enum with `PAID`/`COMPLETED` from day one). The gap was entirely on the consumer side.

## Reachability finding (measured)

`PAID` is **purely latent today — no code path can write it.** Grep-verified every writer of `Booking.status`:
- `POST /api/bookings` (`app/api/bookings/route.ts:165`) hardcodes `status: 'PENDING'` on create.
- `PATCH /api/bookings/[id]` (`app/api/bookings/[id]/route.ts`) validates against a 4-value zod enum that excludes `PAID` (pre-existing, unchanged behavior — see BR-3 below).
- No seed script (`prisma/seed.ts`, `prisma/seed-bookings.ts`) writes `PAID`.
- `grep -rln "payment\|payout" app/api` finds no payment/payout route at all — there is no second write path this story missed.

This is a **trap set for the payment work**, not a live bug a real camper has ever seen — it becomes live the day a payment integration writes `status='PAID'` directly (via a new endpoint, a webhook, or a manual admin action) without anyone remembering to check `lib/booking-status.ts` first. The schema's own `PaymentStatus`/`PaymentMethod` enums (unrelated models, not yet wired to `Booking`) are the concrete signal that this day is coming.

## The fix — `lib/booking-status.ts`

Before:
```ts
export type BookingStatus = "PENDING" | "CONFIRMED" | "CANCELLED" | "COMPLETED";
const STATUS_MAP: Record<BookingStatus, BookingStatusMeta> = { /* 4 entries */ };
```
`Record<BookingStatus, …>` type-checked against the FILE'S OWN hand-written union — exhaustiveness was enforced against a lie, not the real schema.

After:
```ts
import type { BookingStatus } from "@prisma/client";
export type { BookingStatus };
const STATUS_MAP: Record<BookingStatus, BookingStatusMeta> = { /* 5 entries, PAID added */ };
```
`BookingStatus` is now the Prisma-**generated** type. `STATUS_MAP` is exhaustive against the REAL enum by construction — this is the compiler-preferred drift guard the ticket asked for (over a custom `check-*.mjs` script), and it required **zero new dependency/tooling**: the type already existed at `@prisma/client`, generated by the existing `prisma generate` step every `predev`/`pretypecheck`/`pretest`/`build` already runs (`scripts/verify-prisma-client-fresh.mjs`, CAM-579). `PAID: { labelKey: "statusPaid", variant: "success" }` was added alongside.

This exactly mirrors `lib/delivery/status-adapter.ts`'s `STATE_TO_STATUS: Record<TicketState, string>` (`TicketState` imported from the generated delivery-client) — a pattern already proven out elsewhere in this codebase; nothing in that file was touched (read-only reference per the dispatch's explicit out-of-bounds).

No consumer of the 5 render surfaces (`app/bookings/page.tsx`, `app/bookings/[id]/BookingDetailClient.tsx`, `app/bookings/[id]/confirmation/BookingConfirmationClient.tsx`, `app/dashboard/page.tsx`, `app/dashboard/bookings/page.tsx`) needed a code change — every one already calls the shared `getBookingStatusMeta(booking.status)`; fixing the map fixes all five at once (verified: `grep -rln getBookingStatusMeta app` → exactly these 5 files + the util itself).

## Copy (`locales/translations.json`)
Added `bookings.statusPaid` to both locale branches, positioned after `statusConfirmed` (matching the schema's `PENDING → CONFIRMED → PAID → CANCELLED → COMPLETED` order):
- TH: `ชำระเงินแล้ว` — plain language, no jargon, no em-dash, same `...แล้ว` (already-done) suffix pattern as `ยืนยันแล้ว`/`ยกเลิกแล้ว`/`เข้าพักแล้ว`.
- EN: `Paid` — single word, matching the neighboring `Pending`/`Confirmed`/`Cancelled`/`Completed`.

## The second shadow — `app/api/bookings/[id]/route.ts` (found in the same sweep)

Before:
```ts
const BookingStatusEnum = z.enum(['PENDING', 'CONFIRMED', 'CANCELLED', 'COMPLETED']);
```
This is a second, independent hand-written mirror of the same Prisma enum — but it is a **different kind of artifact** than `STATUS_MAP`. `STATUS_MAP` must handle every possible STORED value (a display concern: any real status can appear on a row and must render safely). This zod schema is a **write-side allowlist**: the set of statuses a caller (camper/host/admin) may set through this one generic `PATCH`. Those are not the same shape of correctness — an allowlist is allowed to be a permanent, deliberate SUBSET of the enum.

**Decision: do not add `PAID` here.** Business/security reasoning: payment status must be written by a trusted payment-processor integration (webhook or dedicated endpoint, not yet built), never by a manual status `PATCH` from any authenticated party — letting a camper (or a host) flip their own booking to `PAID` through this endpoint would let them self-report having paid with no verification. This is also consistent with the endpoint's existing permission model (`isCamper` may only set `CANCELLED`; `canHostUpdate` may set `CONFIRMED`/`CANCELLED`/`COMPLETED`) — nothing in the current AC/permission design anticipates a `PAID` transition through this route.

**What was still worth fixing:** the allowlist literal itself had no compile-time protection against a typo or a future rename/removal of one of its four members. Hardened to:
```ts
import type { BookingStatus } from '@/lib/booking-status';
const PATCHABLE_BOOKING_STATUSES = ['PENDING', 'CONFIRMED', 'CANCELLED', 'COMPLETED'] as const satisfies readonly BookingStatus[];
const BookingStatusEnum = z.enum(PATCHABLE_BOOKING_STATUSES);
```
`satisfies readonly BookingStatus[]` checks that every listed literal IS a real, current `BookingStatus` member (catches a typo or a since-removed member) **without** forcing the list to grow every time the enum does (which would be the wrong shape for an intentional subset — the same distinction the ticket's "prefer the compiler" principle still respects: use exhaustiveness where completeness is the correctness property, use a membership check where a curated subset is the correctness property). Zero behavior change — the same 4 statuses are PATCH-settable as before; `PAID` stays a `400 invalid_input` if ever attempted.

## Drift-guard proof — watched it fail, twice

**(1) Direct simulation — matches exactly what happens if `STATUS_MAP` is left behind.** Temporarily removed the `PAID` entry from `STATUS_MAP` (leaving the `Record<BookingStatus, …>` type — i.e. the current, real 5-member enum — unchanged), then ran:
```
$ npx tsc --noEmit
lib/booking-status.ts(24,7): error TS2741: Property 'PAID' is missing in type
  '{ PENDING: {...}; CONFIRMED: {...}; CANCELLED: {...}; COMPLETED: {...}; }'
  but required in type 'Record<BookingStatus, BookingStatusMeta>'.
```
and the new runtime companion test (`__tests__/cam-618-booking-status-paid.test.ts`) went red on 5 assertions, including the `[drift guard]` describe block:
```
FAIL  … [drift guard] … > Object.values(BookingStatus) all resolve to a non-null labelKey
  AssertionError: BookingStatus.PAID must have a mapped labelKey … expected null not to be null
```
Restored the file; both `tsc --noEmit` and the test file returned to green (`11/11 pass`).

**(2) Full schema-level simulation — the literal scenario the ticket describes ("add a member to the schema enum").** `prisma/schema.prisma` is out of this story's file surface to ship a change to (the enum is already correct), so this was done as a temporary, reverted-before-commit local proof, not a shipped diff: added a 6th member `REFUNDED` to the `BookingStatus` enum, ran `npx prisma generate` (regenerating the real client against the modified schema), then:
```
$ npx tsc --noEmit
lib/booking-status.ts(24,7): error TS2741: Property 'REFUNDED' is missing in type
  '{ PENDING: {...}; CONFIRMED: {...}; PAID: {...}; CANCELLED: {...}; COMPLETED: {...}; }'
  but required in type 'Record<BookingStatus, BookingStatusMeta>'.
```
Reverted `prisma/schema.prisma` to the committed version (`git diff` confirmed byte-identical) and re-ran `npx prisma generate` to restore the real client; `npx tsc --noEmit` returned clean (no output). `git status --porcelain` was checked afterward and shows no diff on `prisma/schema.prisma` or `prisma/migrations/**`.

Both proofs together demonstrate the SAME class of drift (schema gains a member; `STATUS_MAP` doesn't) fails the SAME way (`tsc` error TS2741 naming the exact missing member) — a nobody-has-to-remember, unbidden compile error, per the ticket's "prefer the compiler" instruction.
