## Story
As a **Camper** browsing in Thai, I want the camp card to show its location and price honestly in my chosen language, so that I can trust what I'm reading before I open a camp.
Why: three real defects found by the owner testing the live site in Thai — an English-only location line with a hardcoded `Thailand` literal, a price that hides the top of a real range, and a favourite-icon contrast claim that had never been measured. v2 (this revision): the coordinator measured the dev DB directly and found the v1 fix's Thai-name seam (the `Location.thaiLocationId` FK) reached only 12 of 652 camps; separately, the owner changed the requirement — show `district, province`, never the country ("User รู้อยู่แล้ว").
Scope: `components/CampgroundCard.tsx` (render + copy) · the card's location/price data seam (`lib/read-models/camp-card.ts`, `components/CatalogResults.tsx`, `app/api/campsites/route.ts`, `app/wishlist/page.tsx`'s own select) · `locales/translations.json` copy keys. Does NOT touch `lib/campsite-filters.ts`'s province equality match, `prisma/schema.prisma`, or any token/`app/globals.css` value.
Depends on: CAM-531 (province dropdown reads `Location.province` — the field this story must not disturb) · CAM-537 (dark-mode `--primary` contrast fix — the token this story measures, not changes) · CAM-458 (seeded all 77 provinces into `ThailandLocation`/`prisma/data/thailand-locations.json` — the dataset this story's name-based lookup reads)

## Rules
- BR-1 TH-mode province text = the Thai name matched from the seeded province dataset (`ThailandLocation.provinceNameEn == Location.province`, BY NAME) when a match exists; falls back to the raw `Location.province` value (unchanged, whatever is stored) when no match exists — never a client-side Thai/English lookup table, never the `Location.thaiLocationId` FK (see Seams & refs — that FK covers only 12 of 652 `Location` rows in the dev DB, measured).
- BR-2 EN-mode province text = `Location.province` (unchanged pre-existing value/behavior).
- BR-3 The country is NEVER rendered on the card (owner requirement, 2026-07-26: "User รู้อยู่แล้ว") — no `campground.countryName` key, no literal, in either language (proves AC-1/AC-2).
- BR-4 `Location.province` is NEVER changed, renamed, or reshaped by this story — `lib/campsite-filters.ts`'s exact-equality province filter and CAM-531's province dropdown both depend on its current stored value (English).
- BR-5 Price renders as a range (`{low}-{high} /คืน`) only when `priceHigh` is present AND `priceHigh > priceLow`; otherwise renders as a single price (`{low} /คืน`) from `priceLow` alone (proves AC-3/AC-4/EC-2).
- BR-6 A free camp (`priceLow` `null` or `<= 0`) renders `common.free` (`ฟรี`) with no `/คืน` suffix — no range logic runs (proves AC-5).
- BR-7 The `/คืน` (TH) / `/night` (EN) separator is the locale key `common.perNight` — never hardcoded in JSX (proves AC-3/AC-4).
- BR-8 (v2) District is NOT populated for any camp in the DB today (`Location.district` is `null` on all 652 rows, measured) — the card's line is province-only until that data exists. The type/render path accepts a district (`CampgroundCardData.location.district`) so it slots in with NO further code change the moment host-entered district data lands (proves AC-7/EC-4). This is not speculative future code: the branch is real, tested, and reachable the instant the column is populated — it is not exercised today because the DATA isn't there, not because the CODE is incomplete.

## Edge cases
- EC-1 IF `Location.province` has no match in the seeded province dataset (an unmapped/placeholder value, e.g. the dev DB's orphaned `'x'` row) THEN the TH-mode province text falls back to the raw `Location.province` value rather than throwing or blanking the line (BR-1).
- EC-2 IF `priceHigh` is `null`, `undefined`, or `<= priceLow` THEN the card renders the single-price form — never a degenerate/inverted range like `1,000-500` (BR-5).
- EC-3 IF the camp is free THEN no `/คืน` suffix renders alongside `ฟรี` (BR-6) — this is a change from the pre-existing behavior (which showed `ฟรี คืน`), made because the same price block is being restructured anyway.
- EC-4 (v2) IF `Location.district` is absent (true for every camp today) THEN the location line renders province-only, with no dangling separator or stray comma (BR-8).

## Data
- `Location.province` (existing column) — READ-ONLY, unchanged. `Location.district` (existing column, currently `null` on all rows) — now READ by the card's select, rendered when present (BR-8). `ThailandLocation` (existing table, 77 province-level rows seeded by CAM-458) / `prisma/data/thailand-locations.json` (the same 77 rows, as a static asset) — READ by a new name-based lookup (`getProvinceThaiNameMap`), matching `provinceNameEn` against `Location.province`. `CampSite.priceHigh` (existing `Decimal?` column, already written by the host form) — now READ and rendered by the card for the first time. No schema change; no migration.
- Measured coverage (dev DB, captured 2026-07-26): 650 of 650 real `CampSite` rows (100%) now resolve a Thai province name via the name-based match; 77 of 78 distinct `Location.province` values match (the sole miss, `'x'`, is an orphaned `Location` row with zero live `CampSite` attached — verified via `campSite.count({where:{location:{province:{in:[...matched]}}}})` === `campSite.count()`). The prior FK-based approach (`Location.thaiLocationId`) reached 12 of 652 `Location` rows.

## Out of scope
- `components/CampgroundDetailClient.tsx` has the SAME hardcoded `, Thailand` bug at two call sites (its own address line + a detail-page location row) — that file is outside this story's allowed surface (only `CampgroundCard.tsx` was in scope) → needs its own follow-up ticket, and should apply this same district/no-country pattern when it's fixed.
- A "starting from" (lowest-price-only) copy variant was considered and rejected in favor of showing the real range — see Rules BR-5 rationale: `priceHigh` is a concrete host-set upper bound, not a synthetic derived minimum, so showing the full range is more honest than truncating it.
- Populating `Location.district` for any camp — that is host-data entry / a backfill, not a display-layer story; out of scope here (BR-8/EC-4 only wire the render path).
