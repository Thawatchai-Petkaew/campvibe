# Asking for a district by name still finds nothing, because the model is never told districts are searchable (CAM-596)

## Story
As a **Camper**, I want asking น้องกองไฟ for a campsite by อำเภอ (district) name alone — with no province mentioned — to actually search that district, so that "ลานกางเต็นท์แม่ริม" finds the real Mae Rim camps instead of answering "ไม่พบ".
Why: CAM-587 wired `district`/`subDistrict` into the `searchCampsites` TOOL and proved the resolution layer works (`district:"แม่ริม"` → 6 cards, called directly). But nothing makes the MODEL actually set the argument: the tool's own headline description never mentions district/sub-district (only province/region/type/…), and the deterministic place pre-pass (`lib/ai/place-resolver.ts`) that already forces a MANDATORY province/region/near hint has no district equivalent — so the model is left to recognise a district from its own training knowledge, and its own `district` parameter description correctly tells it to leave the field unset rather than guess when it doesn't recognise a place. The model cannot recognise แม่ริม; only the database can. The owner reproduced this on a freshly restarted dev server, 2026-07-28.
Scope: extend the deterministic pre-pass (`resolvePlace`) to also detect an อำเภอ (district) name in the camper's free text, using the SAME static gazetteer (`prisma/data/thailand-locations.json`) it already scans for provinces — never a new DB-backed lookup path in the pre-pass itself. Update the tool's headline description to name district/sub-district as searchable axes, and soften (never remove) the "don't guess" per-parameter guidance so it no longer contradicts a server-issued hint. The actual district/sub-district RESOLUTION (`resolveDistrictAdminAreaIds`/`resolveSubDistrictAdminAreaId`, both already calling the shared `matchAdminArea`, CAM-566) is proven correct and is not touched. No schema/migration.
Depends on: CAM-587 (wired district/subDistrict into the tool; this story is its gap), CAM-566 (shared `matchAdminArea`), CAM-501/502/503/504 (the existing province/region/near/landmark pre-pass this story extends), CAM-463 (the honest-failure precedent this story must not break).

## Rules
- BR-1 Precedence in the pre-pass mirrors the tool's own real precedence (`near` > `district` > `province` > `region`, CAM-587 BR-1): the landmark check and the proximity/Bangkok-bare check (both unchanged, CAM-502/503/504) run FIRST; only if neither fires does the new district detector run; only if THAT finds nothing does the existing plain-province/region detection run. A district hint therefore never overrides a landmark or a proximity ("ใกล้/แถว/รอบๆ") ask — those keep exactly their current CAM-502/503 behavior.
- BR-2 A province mentioned in the SAME message as a resolved district is still detected and attached alongside it (both fields set at once) — it is consulted only as a scoping hint by the existing, unchanged `resolveExactInsideAdminAreaIds`, never as a competing top-level filter (proves AC-4, mirrors CAM-587 BR-1's own province-as-scope framing).
- BR-3 Detection is a plain, deterministic free-text scan against the same static gazetteer already imported for provinces (`prisma/data/thailand-locations.json` — the exact seed source of the live `AdminArea` table `matchAdminArea` queries, CAM-553/562), never a DB round-trip inside the pre-pass — the pre-pass only decides WHETHER to hint; the ACTUAL resolution stays entirely inside the existing, unchanged, `matchAdminArea`-backed `resolveDistrictAdminAreaIds`. A pre-pass false positive is never silently wrong: it is caught downstream by the same honest-empty path AC-2 already proves.
- BR-4 Substring-collision guards (the DEF-1/DEF-2 lesson, CAM-501/503), applied at candidate-list build time, never by weakening `matchAdminArea` into a `contains` scan:
  - A candidate shorter than 4 Thai characters is excluded entirely (mirrors `AMBIGUOUS_PROVINCE_NAMES_TH`'s existing curated-short-name treatment).
  - A candidate that is a substring of ANY real province's Thai name — including an EXACT match — is excluded entirely. Measured, not hypothetical: อุทัย⊂อุทัยธานี, หนองบัว⊂หนองบัวลำภู, พนม⊂นครพนม are each a district in a DIFFERENT, unrelated province (a naive scan on "แคมป์อุทัยธานี" fired `district="อุทัย"` scoped to the WRONG province and broke the search — caught by this story's own red-then-green regression test); "พระนครศรีอยุธยา" as a district is an EXACT duplicate of its own province's name (`detectProvince` already resolves that bare mention correctly).
  - A district literally named "เมือง" + its own province's name (the provincial-capital-district pattern, measured 75 occurrences) is excluded entirely — the plain province name is always co-present as a substring in this exact pattern, so the existing province detection already covers the camper's intent; a colloquial "เมือง" prefix elsewhere in a sentence must never narrow a province-shaped ask down to one specific district. Proven RED before this guard on "อยากไปเที่ยวเมืองเชียงใหม่".
  - Any district candidate starting with "เมือง" (the 4 non-capital-pattern exceptions) or "ท่า" (measured: a common, standalone Thai word for "pier/dock", 23 district names) requires a camping-context marker (reusing the existing `hasCampingContextMarker`) to fire — the same context-guard treatment CAM-503-DEF-2 already gave "เขาใหญ่"/"เขาหลัก".
  - A candidate already in the existing `AMBIGUOUS_PROVINCE_NAMES_TH` curated set is excluded, reusing that one set rather than a second curated list.

## Edge cases
- EC-1 IF the district candidate found in the text requires a camping-context marker (BR-4) and none is present THEN the pre-pass does not hint it — the message falls through to plain province/region detection (or no hint at all), exactly as it did before this story; the model may still set `district` on its own initiative per the tool's (softened) parameter description, but nothing forces it to.
- EC-2 IF the message names only a province (no real district substring survives the BR-4 guards) THEN only `province` is hinted — byte-identical to the pre-CAM-596 prompt for every such message (regression guard, proves AC-3).
- EC-3 IF a proximity marker (ใกล้/แถว/รอบๆ/ย่าน/บริเวณ) is present together with a district name THEN the district still resolves normally (the tool's own `near` description already tells the model never to use `near` for a district/town) — a proximity marker only changes how a PROVINCE mention resolves (`near` vs `province`), never a district mention.

## Data
No schema/migration. No new entity/field — reuses `prisma/data/thailand-locations.json` (already imported by `place-resolver.ts` for province detection) and the existing `AdminArea` table (unchanged, CAM-553/562/566/587).

## Seams & refs
- Reuse: `lib/ai/place-resolver.ts`'s existing `resolvePlace`/`detectProvince`/`detectRegion`/`detectLandmark`/`hasCampingContextMarker` idioms (longest-match-first, context-guard, curated ambiguous-name exclusion) — the new district detector is a new candidate list scanned with the SAME mechanism, not a new one. `lib/geo/admin-area-match.ts`'s `matchAdminArea` (CAM-566) and `lib/ai/tools/search-campsites.ts`'s `resolveDistrictAdminAreaIds`/`resolveSubDistrictAdminAreaId` (CAM-587) are reused UNCHANGED — this story never touches them (out of file surface). ## Out of scope
- **Sub-district free-text detection — measured unsafe, not merely deferred for time.** v1 of this spec planned it (mirroring district exactly, gated by an ALWAYS-required camping-context marker). Building it and running it against the existing `cam-501` regression suite proved the guard gives NO real protection at sub-district scale: real sub-district names "เหนือ" (above/north), "กลาง" (middle), and "ตากแดด" (sunbathe, literally a real sub-district in 3 separate provinces) all fired even WITH a camping-context marker present, because nearly every message this camping assistant ever receives already contains one ("ที่กางเต็นท์"/"กางเต็นท์"/etc.) — the guard that works for a landmark like เขาใหญ่ (rare outside camping talk) provides no signal here. The model may still set `subDistrict` on its own initiative (the tool's parameter description, softened the same way `district`'s was) — a bare ตำบล mention gets no pre-pass hint, unchanged from before this story. → follow-up CAM ticket only if a curated, evidence-based sub-district guard design emerges (e.g. an explicit allow-list rather than a blanket context requirement).
- Free-text detection of `place-aliases.json`'s `zoneAliases` (e.g. "หัวหิน" as a colloquial zone name, distinct from its own real district-name entry which IS covered here) — that file's own docblock states it is deliberately safe only at the ISOLATED-tool-argument layer (no `contextGuard` enforcement), not as a free-text scanner; adding it to the pre-pass would need its own guard design. → follow-up CAM ticket if evals show a systematic miss.
- A general, exhaustive curated list of every common-word district prefix (บ้าน, วัง, ดอน, คลอง, หนอง, บาง, …) — this story guards specifically the two prefixes measured against the real bug ("เมือง", "ท่า"); the broader class is accepted under the same EC-4/BR-1 substring tolerance the province/region/landmark detectors already carry. → follow-up CAM ticket if evals show a systematic miss on one of these.
