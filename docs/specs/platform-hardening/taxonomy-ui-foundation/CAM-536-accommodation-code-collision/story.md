## Story
As a **Host**, I want to select and remove EVERY one of the 6 accommodation types my camp offers (including tent site and horse camp), so that no accommodation-type meaning is permanently stuck-on or permanently unselectable because of an unrelated internal code collision.
Why: CAM-526 seeded the `Accommodation type` MasterData group but could only place 4 of the 6 `AccommodationTypeEnum` members — `TENT` was already owned by `group: 'Equipment for rent'` and `HORS` was already owned by `group: 'Activity'` (`MasterData.code` is a global `@id`, not scoped per group). The 2 excluded meanings ("tent site", "horse camp") were left in the zod enum but had no seeded row: a host could neither select nor remove them in the picker, and — because a camp's existing CSV value round-trips through save without the form ever rebuilding it from the (empty) rendered options — 486 dev camps already carry the unmanageable `TENT` value and 27 carry `HORS`. Owner decision (2026-07-26, "ตามแนะนำ"): give the two colliding meanings their own distinct codes and backfill.
Scope: rename the 2 colliding `AccommodationTypeEnum` members to distinct MasterData codes (`TENT`→`TSIT` "Tent site", `HORS`→`HCMP` "Horse camp"), seed both under `group: 'Accommodation type'` with real Thai/English names + an icon, backfill every existing `CampSite.accommodationTypes` CSV value from the old codes to the new ones, and prove the backfill whole-value-safe + idempotent. Does NOT touch `MasterData.code`'s schema (stays a global `@id`, no migration), does NOT touch the pre-existing `Activity: HORS` (ขี่ม้า) or `Equipment for rent: TENT` (เต็นท์) rows, does NOT touch `CampgroundForm.tsx` / `CampgroundDetailClient.tsx` / any API route (the picker and detail section already render whatever is seeded — no component change needed).
Depends on: CAM-526 (the story that first hit this collision and documented it as BR-2/Out-of-scope).

## Rules
- BR-1 `AccommodationTypeEnum` (`lib/validations/campsite.ts`) renames its 2 colliding members: `HORS` → `HCMP` ("Horse camp"), `TENT` → `TSIT` ("Tent site"). The other 4 members (`CABI`/`DISP`/`GROU`/`RECR`) are unchanged. Both new codes are seeded under `group: 'Accommodation type'` in `prisma/seed.ts` with a real Thai + English name and an icon reused from the existing import list (`Tent` for `TSIT`, `PawPrint` for `HCMP` — both already imported in `lib/facility-icon-map.ts` for the pre-existing `CAGD`/`HORS` rows), matching the CAM-513 precedent for resolving a global-`@id` collision by giving the new meaning its own code rather than converting `MasterData.code` to a composite key (proves AC-1).
- BR-2 The pre-existing `Activity: HORS` (ขี่ม้า / Horseback riding) and `Equipment for rent: TENT` (เต็นท์ / Tent) MasterData rows are **not modified** by this story — same `group`, `nameTh`, `nameEn`, `icon` as before. `lib/ai/tools/search-campsites.ts`'s `ACTIVITY_CODES`/`EQUIPMENT_CODES` constants (which reference `HORS`/`TENT` for those unrelated groups) need no change (proves AC-5).
- BR-3 A backfill script (`scripts/backfill-cam-536-accommodation-codes.mjs`) rewrites every `CampSite.accommodationTypes` CSV value: each comma-separated value is looked up **whole**, never via a substring/global string replace (`TENT`→`TSIT`, `HORS`→`HCMP`); every other value in the same CSV (including a value that merely contains "TENT"/"HORS" as part of a longer token, none exist in real data today but the transform must be safe regardless) passes through byte-identical, and value order is preserved (proves AC-2/AC-3).
- BR-4 The backfill is idempotent: a row is written only when its transformed CSV differs from the stored value, so a second run against the same database updates 0 rows. The backfill never calls `deleteMany`; it only rewrites the `accommodationTypes` column via targeted `update` calls scoped to rows that actually changed.
- BR-5 The backfill script refuses to run unless `ALLOW_ACCOMMODATION_BACKFILL=1` is set, `DATABASE_URL` is set, and the target does not look like production (URL contains `prod`, or `NODE_ENV`/`VERCEL_ENV=production`) — mirrors the existing guard in `scripts/db-reset.mjs`/`scripts/seed-demand.mjs`; console output prints only scheme+hostname (`describeUrlShape`, reused from `db-reset.mjs`), never path/query/credentials.
- BR-6 No schema/migration change: `MasterData.code` stays a global `String @id` (unchanged Prisma schema) — this story is a data-only rename + backfill, per the owner decision to follow the CAM-513 precedent rather than convert to a composite key.

## Edge cases
- EC-1 IF the host has zero of the 6 accommodation-type tiles selected THEN the section still renders all 6 selectable tiles (no rows hidden), matching CAM-526's existing empty-gate behavior for the picker itself (BR-1)
- EC-2 IF a camp's `accommodationTypes` CSV contains ONLY the old colliding code (e.g. `"TENT"` or `"HORS"`) THEN the backfill rewrites the whole value (`"TSIT"` / `"HCMP"`), not a partial string (BR-3)
- EC-3 IF a camp's `accommodationTypes` CSV mixes a colliding code with a safe code (e.g. `"TENT,CABI"`, `"HORS,GROU"`) THEN only the colliding value is renamed; the safe value and the comma-separated structure are preserved exactly (BR-3)
- EC-4 IF the backfill script runs a second time against an already-migrated database THEN it updates 0 rows (idempotent — BR-4)
- EC-5 IF `ALLOW_ACCOMMODATION_BACKFILL` is unset, or `DATABASE_URL` is unset, or the target URL/env looks like production THEN the script refuses and exits non-zero before touching any row (BR-5)
