# The tambon shortlist is missing 74 places that really do have camps (CAM-606)

## Story
As the **Camper**, I want the sub-district (ตำบล) shortlist to include every tambon that currently holds a camp, so that naming one of them returns the camps it actually has instead of the honest "place not recognised" path answering correctly about stale data.
Why: CAM-605's drift check found, on its very first real run, that the committed shortlist (422 rows, generated against a dev DB holding ~650 camps) undercounts the live fact (795 camps, 503 camp-holding tambons) by 74 names. This is not a CAM-600 defect — the artifact was correct for the data in front of it at generation time — but it is stale at birth rather than drifting later, and closing it now is a straight re-run of the existing, unmodified generator.
Scope: regenerate `prisma/data/subdistrict-shortlist.json` via the existing, unmodified `scripts/generate-subdistrict-shortlist.mjs` against the current dev DB, and confirm `scripts/check-subdistrict-shortlist-drift.mjs` (CAM-605, also unmodified) reports 0 drift afterwards. Does not touch `lib/ai/place-resolver.ts`, its guards, or either script — this story is a data regeneration + behavioral proof, not a code change.
Depends on: CAM-600 (the shortlist + generator) · CAM-605 (the drift check that found the gap).

## Rules
- BR-1 The regenerated artifact is produced ONLY by re-running the existing, unmodified `scripts/generate-subdistrict-shortlist.mjs` — never hand-edited. A hand-edit cannot be trusted to match the live "holds a camp" fact and would defeat the entire point of a generated artifact (CAM-600 tech.md).
- BR-2 The regeneration must be a pure addition against the current committed file for this story to be in scope: CAM-605's own drift check, run BEFORE regenerating, must report a non-empty `added` set and an EMPTY `removed` set (measured: 74 added, 0 removed). A non-empty `removed` set (camps that closed) would be a different, legitimate finding but is not what this story addresses — none was found.
- BR-3 No guard in `lib/ai/place-resolver.ts` changes. The regenerated file is raw data; CAM-600's guards (length floor, ordinary-vocabulary skip-set, substring-of-any-province, within-shortlist collision-scoping) apply to it exactly as they already do to the smaller list, unmodified.
- BR-4 Every newly-added name is inspected for collision risk (short and/or ordinary Thai vocabulary) before shipping. A doubtful name is named explicitly in the PR/ticket rather than silently shipped, even when the existing guards technically let it through — per the ticket's own instruction that a longer list is a wider collision surface.
- BR-5 If regenerating and re-running the guarded negative cases reveals that the LARGER list breaks an existing guard (a negative case starts resolving to a place, or a sibling fixture regresses), that is reported as a finding — CAM-600's guard set would then be insufficient at this size, which is a different story with a different fix. This story does not attempt that fix.

## Edge cases
- EC-1 IF the regenerated file's raw row count does not increase and the `removed` set is non-empty THEN this is NOT the pure-addition case this story addresses — investigate before committing. Measured here: raw rows 422 → 503 (81 new raw rows, 0 removed, confirmed via `git diff --stat`); two names (นาบัว, บางเตย) each contribute 2 of those raw rows (a second, different-province entry for an already-colliding name), so 79 raw-new rows are unique names; running `computeDrift` (the guard-filtered comparison the real check performs) between the pre- and post-regeneration files reports exactly 74 added / 0 removed — the subset of those 79 unique new names that also survive the length floor/skip-set/substring-of-province guards. Both counts are real and consistent (74 ⊆ 79 ⊆ 81); they are not the same measurement and are not expected to arithmetically reduce to one figure.
- EC-2 IF `check:subdistrict-drift` reports anything other than "0 drift" after regeneration THEN the regeneration is incomplete or the DB changed between the generate and check calls — re-run both against a stable snapshot.
- EC-3 IF a newly-added tambon name is ambiguous within the shortlist (repeats across >1 province) THEN a bare, unscoped mention must still fall through to the next coarser level (unchanged CAM-600 `resolveAmbiguousSubDistrictEntry` behavior) — not asserted per-name in this story's tests beyond what CAM-600's own suite already covers structurally.
- EC-4 IF any of the six CAM-600 negative phrases resolves to a non-empty object after regeneration THEN CAM-600's guard set has a real gap at this larger size — STOP, do not patch the guards under this ticket, report it as a finding for a follow-up story.
- EC-5 IF a sibling fixture (แม่ริม/อำเภอปาย/เชียงใหม่/ใกล้เขาใหญ่) regresses THEN the regeneration introduced an unexpected interaction — investigate before committing (none found: all four confirmed unchanged).
