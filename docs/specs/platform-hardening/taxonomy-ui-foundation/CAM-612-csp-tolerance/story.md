## Story
As the **Platform** (delivery team), I want the CSP-violation cap in `e2e/regression/cam-607-csp-nonce-agreement.spec.ts` tightened from `<= 1` to `0` now that the one violation it was written to tolerate is fixed, so that the regression suite cannot silently keep tolerating a violation that no longer happens — the exact "cap nobody re-reads" hole named in `.claude/rules/qa.md` (CAM-201) and this ticket's own reporter, CAM-610.
Why: CAM-607 wrote the `<= 1` cap honestly, because at the time `next-themes`'s own FOUC-prevention script was still un-nonced and CAM-607 was not the story fixing it. CAM-610 then fixed that exact gap and measured zero violations across a real production build — leaving the `<= 1` cap stale. A stale tolerant cap passes forever and would not fail on the day a NEW un-nonced script appears, which is precisely the failure shape this family (CAM-218 → CAM-607 → CAM-610) keeps repeating.
Scope: tighten the cap to `0` in the one file named above; confirm it still passes for the real reason (zero measured violations, not because the assertion stopped running); decide, explicitly, whether this spec and CAM-610's own `cam-610-theme-script-nonce.spec.ts` now duplicate the same invariant closely enough to merge one into the other. Does not touch `proxy.ts` / `components/Providers.tsx` / `app/layout.tsx` — the CSP and the nonce-threading fix are correct; if the tightened assertion had failed against the real, unmodified app, this story would stop and report that as a finding, not adjust the app to fit the test (none occurred — see `tech.md` for the real, measured run).
Depends on: CAM-607 (`cam-607-csp-nonce-agreement.spec.ts`, the file this story edits) · CAM-610 (`cam-610-theme-script-nonce.spec.ts` + `tech.md`, the fix and measurement this story's tightened cap now assumes)

## Rules
- BR-1 The tightened cap is `expect(cspViolationLines.length).toBe(0)` — exact equality, not `toBeLessThanOrEqual(0)` (which reads the same at runtime but `.toBe(0)` states the intent — zero, not "at most zero" — more directly for the next reader). (proves AC-1)
- BR-2 The teeth-proof (AC-2) is verified locally by a temporary, NEVER-committed edit (add an un-nonced `<script>`, rebuild, observe red; revert, rebuild, observe green) — not shipped as a permanent test fixture or a permanent app-code change, and `git diff`/`git status` confirm the app tree is clean before the PR is opened. (proves AC-2)
- BR-3 The overlap decision (AC-3) is recorded in `test.md` regardless of outcome (merge or keep-both) — never silently resolved by doing nothing. (proves AC-3)
