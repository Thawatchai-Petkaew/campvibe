## Story
As a **Camper** using a screen reader on the Thai-language site, I want every control's accessible name to actually be in Thai, so that I never hear an English label sitting in the middle of an otherwise-Thai page.
Why: CAM-558 (touch-target floor) measured and enlarged the camp-card carousel arrows and the navbar language switcher, and spotted along the way that both carry hardcoded English `aria-label` string literals (`"Previous image"`/`"Next image"`/`"Switch language"`) — but `e2e/regression/cam-549-*.spec.ts` pins those exact English strings, so fixing the label in the same story as the touch-target resize would have meant editing another story's test to make its own unrelated change pass. CAM-558 reported it instead (its own `story.md` "Out of scope") rather than fix-and-hide the coupling. This story does both: moves the labels to i18n AND updates the pinned assertion that was blocking it.
Scope: move the 3 hardcoded English `aria-label`s (camp-card prev/next arrows, navbar account-menu trigger) plus the 1 CAM-558 flagged (language switcher) into `locales/translations.json` (en + th); update the CAM-549 e2e assertion, plus (authorized mid-story, see Changelog v2) CAM-558's own vitest guard and e2e spec, so every place that located these controls by the old English literal instead sources the expectation from `locales/translations.json`; sweep `components/**` for the same hardcoded-`aria-label` pattern and report the full result (fixed here / found-and-left / already-clean).
Depends on: CAM-558 (`story.md` "Out of scope" — named this exact coupling and deferred it here) · CAM-549 (the e2e spec whose assertion this story updates)

## Rules
- BR-1 Every accessible name (`aria-label`) on a user-facing interactive control resolves from `locales/translations.json` via the active `language` — never a hardcoded JSX string literal. (proves AC-1, AC-2, AC-3, AC-4)
- BR-2 A moved label is a MEANINGFUL translation in both languages, not a literal word-for-word mirror that reads oddly to a Thai screen-reader user (e.g. `nav.accountMenuAriaLabel` is `เมนูบัญชีของฉัน`, "my account menu" — not a stiff literal "เมนูผู้ใช้"). (proves AC-2)
- BR-3 Reuse an existing translation key over adding a new one when one already covers the exact same UI meaning — the camp-card arrows reuse `gallery.previousImage`/`gallery.nextImage` (the same photo-navigation copy `ImageGallery.tsx` already uses) rather than adding a duplicate `campground.*` pair. (proves AC-1)

## Edge cases
- EC-1 IF the sibling e2e spec `e2e/regression/cam-549-no-horizontal-scroll.spec.ts` asserts the language switcher's accessible name THEN it reads the expected string from `locales/translations.json` (the same source the app renders from) rather than re-pinning a literal — the assertion still proves "findable + correctly labelled", it is updated, not weakened or deleted (BR-1).
- EC-2 IF a sibling test suite pins one of the 4 moved literals THEN it is re-anchored on the translation source or a stable non-copy anchor (never a second hardcoded literal), and it must keep proving its ORIGINAL guarantee — CAM-558's guards exist to prove a control is findable and ≥44×44px, not to pin any particular English wording; the touch-floor assertions themselves are untouched (BR-1). Found during the sweep and fixed after orchestrator authorization (Changelog v2): `__tests__/cam-558-touch-floor.test.ts` (was pinning `aria-label="Switch language"` directly and slicing on the literal `"Previous image"`/`"Next image"`) and `e2e/regression/cam-558-touch-targets.spec.ts` (same 4 literals, 8 call sites).
