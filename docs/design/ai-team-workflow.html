STOP RULES (universal — ทุก agent ทุก dispatch)

  1. Repo reality ขัดกับ ticket/spec → หยุดเธรดนั้น รายงาน conflict ห้ามด้นสด redesign เอง
  2. Error ซ้ำสอง → บันทึกแล้วข้าม หรือรายงาน ห้าม loop
  3. ห้ามแตะไฟล์นอก file surface ที่ dispatch ระบุ
  4. ห้ามเพิ่ม dependency/endpoint/schema ใหม่นอกเหนือ ticket → ถ้าจำเป็นให้หยุดแล้วรายงาน

Stall watchdog + circuit breaker (build phase)

Dispatch เงียบ (ไม่มี commit/mtime ใหม่) เกิน ~15 นาที (build) หรือ ~25 นาที (research) = presumed stalled: ตรวจ ground-truth (git log/ticket-sync show) → kill dispatch (ไม่ปล่อยรันไม่จำกัด) → re-dispatch โดย resume จาก artifact เดิม (branch/ไฟล์/commit ที่มีอยู่) ไม่เริ่มใหม่ (ที่มา: CAM-268 silent-death incident)

Circuit breaker (Shape Up adaptation) อยู่ที่ระดับ gate ไม่ใช่ dispatch เดี่ยว — ดู §5

Parallel dispatch (owner rule 2026-07-03): อนุญาตให้รันหลาย agent พร้อมกัน โดย main working tree มี code-writer ได้สูงสุด 1 ตัว; ตัวเพิ่มเติมทุกตัวต้องรันใน isolation: "worktree" บน branch แยก + partition file surface ไม่ให้ทับกัน; agent read-only (Explore/Plan/security review) รันขนานได้ไม่จำกัด; merge ยังคง serial เสมอ (gh pr update-branch + CI re-run ระหว่างแต่ละ merge)

กันสนิม (anti-rubber-stamp — ไม่ใช่ตัวเลือกเสริม)

Retro replay — ทุก /retro เล่นซ้ำ gate rejection ทั้งหมด + ความล้มเหลวจริงอย่างน้อย 1 เคสให้เจ้าของดู (งานวิจัย automation-bias: ~41% ของปัญหาหายไปจาก summary ถ้าไม่โชว์ failure ตรงๆ)
Spot-audit — เจ้าของสุ่มตรวจ standard-class G2 pass เป็นระยะ (ไม่ใช่ทุกอัน — ไม่งั้นเสียจุดประสงค์ pre-authorization)
Graduated-autonomy ledger — class ใหม่ต้องมี ~20 clean approval + owner ให้สัตยาบันชัดเจนก่อนใช้จริง
Circuit breaker — reject 2 ครั้งบน story เดียวกัน = หยุด rework ทันที กลับเข้า Discovery ให้ re-shape spec (AC แคบลง/scope แคบลง/แก้ assumption) แทนการลองครั้งที่ 3 แบบสุ่ม; miss ใดๆ ของ pre-authorized class = demote class นั้นกลับ full-tap ทันที (safety valve ไม่ใช่ exception ครั้งเดียว)
