Camper-facing

  • Catalog / discovery / search / filters (~128 แคมป์)
  • หน้า detail + image gallery
  • Wishlist
  • Verified-stay reviews (CAM-269 — ส่งวันนี้: เฉพาะ stay ที่เข้าพักจริงเท่านั้นรีวิวได้ + list แสดงเฉพาะรีวิว verified)
  • Reserve flow (booking สถานะ PENDING เท่านั้น ไม่มี payment — เก็บไว้เป็น internal foundation ตาม ADR-011 ไม่ใช่ camper-facing checkout จริง)
  • Google OAuth (กำลังทำ, CAM-233)

Host-facing

  • Host dashboard (listing/spot CRUD, booking management)
  • Availability lib + remaining-capacity API (CAM-267)
  • Team RBAC — 5 roles / 13 permissions

Platform + AI delivery system

  • Design system v2 + loading UX
  • Performance / Core Web Vitals hardening
  • Security hardening (strict CSP nonce)
  • Self-hosted delivery ticket system — /status + /status/map + Telegram gates (ADR-010) — the AI delivery team ทำงานเอง

Prod state

  • campvibe.vercel.app live ตั้งแต่ 2026-06-28 (v0.11.0)
  • เป็นหน้า Coming Soon gated ด้วย flag COMING_SOON=1 — full app ยังซ่อนอยู่

7 Guardrails (4 ข้อ บังคับทุก milestone) + Gate loop G1–G5

1. AI ไม่ auto-publish แผนที่ — ทุก draft ที่ AI สร้าง (แผนที่/โซน/ข้อมูล) ต้องให้ host ยืนยันก่อนเผยแพร่เสมอ
2. AI ไม่เขียนเงิน/availability โดยไม่ผ่าน host ยืนยัน — AI drafts/summarizes/suggests เท่านั้น ไม่ commit การเปลี่ยนแปลงที่กระทบเงินหรือที่ว่างโดยตรง
3. Deterministic core vs AI-assist layer แยกกันชัด — ledger, availability, state transitions, daily-close math ต้อง deterministic; AI อยู่ใน layer แยกที่ทำได้แค่ draft/summary/suggestion
4. กฎคำ CTA — ตราบใดที่ campsite นั้นยังไม่ผ่าน BookingReadinessGate ปุ่ม/ข้อความที่ดูเหมือน "จอง" ต้องเปลี่ยนเป็น สอบถาม/ขอราคา/ส่งคำขอ เสมอ

Gate loop (ทุก milestone เดินผ่านลูปนี้ — เจ้าของอนุมัติทุก gate เอง ไม่มี autonomous approval)
