03Bounded agent loop

หลักการBounded/guarded agent looptool_choice forcingCircuit breaker / model fallbackWall-clock deadline
techOpenRouter chat/completionsfunction-calling (tools schema)AbortSignal.timeout
  1. Self-skip: ไม่มี OPENROUTER_API_KEY → คืน {ok:true, skipped:true} ไม่ยิง network
  2. วน iteration = 1..4 — เช็ค deadline (>40s) ก่อนยิงรอบใหม่
  3. รอบสุดท้าย (iter 4) = forced tool_choice:'none' → บังคับตอบเป็น prose
  4. รอบ 1 เท่านั้น: model fallback ครั้งเดียว (primary→fallback) แล้ว pin โมเดลที่ตอบ
  5. ไม่มี tool_calls / ว่าง / forced → finalize (ดึง suggestions ออก)
  6. มี tool_calls → executeToolCalls ด้วย roundLimit = min(3, 6 − executed) → append ผลลง messages → วนต่อ

05Injection defense & provenance fencing

หลักการPrompt-injection defenseData ≠ instruction separationProvenance labelingAnti history-poisoning
techsanitizeForPromptwrapAsUserData (<user_message>)zod bounds
  • ทุก user turn → wrapAsUserData(sanitizeForPrompt(text)) = ห่อใน <user_message> fence (data เสมอ)
  • assistant turn (guest/client mode) → ห่อเป็น DATA + ป้าย "คำตอบก่อนหน้า (อ้างอิง)" — client อ้าง assistant reply ไม่ได้ trust สูงขึ้น (anti-poisoning)
  • assistant turn (server mode, Path C) → เป็น real assistant message (เพราะมาจาก DB ที่เรา persist เอง = เชื่อได้)
  • NFKC ไม่ใช้ (ทำ SARA-AM ไทยเพี้ยน) · fence regex ทน zero-width/digit bypass (CAM-471)
ศึกษาต่อ: OWASP LLM01 Prompt Injection · data/instruction separation · content provenance.
