# คะแนนความครบของ listing แบบ rule-based พร้อมรายการที่ยังขาด (CAM-304)

## Why

โฮสต์ไม่รู้ว่า listing ของตัวเอง "พร้อมขาย" แค่ไหน (ราคา/นโยบาย/รูปครบไหม) ทำให้ข้อมูลที่ผู้ใช้เห็นไม่สมบูรณ์และลูกค้าไม่กล้าตัดสินใจ. KPI: สัดส่วน listing ที่คะแนน ≥ เกณฑ์ที่กำหนด (not measured, ตั้ง baseline หลัง ship).

## Story

ในฐานะ Host ฉันต้องการให้ระบบคำนวณคะแนนความครบของ listing ของตัวเอง พร้อมรายการที่ยังขาดเป็นรายข้อ เพื่อรู้ว่าต้องแก้อะไรก่อนลูกค้าจะเห็นข้อมูลไม่ครบ
Scope: คำนวณคะแนน 0-100 แบบกำหนดกฎตายตัว (ไม่ใช้ AI, ผลลัพธ์เดิมซ้ำได้เสมอ) จากความครบของฟิลด์ atomic (รูปขั้นต่ำ, ราคา, ค่าธรรมเนียม, นโยบายยกเลิก, โซน/สิ่งอำนวยความสะดวก) พร้อมคืนคะแนนและรายการข้อที่ยังขาดเป็นรายข้อ. ไม่รวมหน้าจอแสดงผล (ดูสตอรี่ถัดไป)

## AC

| # | Given | When | ผลที่ผู้ใช้เห็น | ผลเชิงข้อมูล |
|---|---|---|---|---|
| AC-1 | ลานยังไม่มีรูปภาพและยังไม่กรอกนโยบายยกเลิก | คำนวณคะแนนความครบของลานนั้น | คะแนนต่ำกว่า 100 พร้อมรายการระบุ `ยังไม่มีรูปภาพ` และ `ยังไม่ระบุนโยบายยกเลิก` | คำนวณคะแนนจากน้ำหนักฟิลด์ที่กำหนดไว้ทุกครั้งแบบสด ไม่มีค่าค้างจากรอบก่อน |
| AC-2 | โฮสต์เพิ่งแก้ไขข้อมูล (เช่น เพิ่มรูป, กรอกนโยบายยกเลิก) | คำนวณคะแนนอีกครั้งหลังบันทึกข้อมูลใหม่ | คะแนนสูงขึ้นตามฟิลด์ที่เพิ่งครบ | คะแนนคำนวณจากสถานะฟิลด์ล่าสุดเสมอ ไม่มีค่าเก่าค้างอยู่ |
| AC-3 | ลานกรอกข้อมูลครบทุกฟิลด์ตามเกณฑ์ | คำนวณคะแนนของลานนั้น | คะแนน = 100 และรายการที่ขาดว่างเปล่า | รายการข้อที่ขาดเป็นค่าว่าง |
| AC-4 | ลานขาดหลายฟิลด์พร้อมกัน | คำนวณคะแนนของลานนั้น | รายการที่ขาดระบุทีละข้อชัดเจน ไม่รวมเป็นข้อความเดียวคลุมเครือ | แต่ละรายการที่ขาดมีตัวระบุฟิลด์ที่ชัดเจน สำหรับให้หน้าจอในสตอรี่ถัดไปเชื่อมลิงก์ไปถูกจุด |

## Rules

- BR-1 สูตรคะแนนต้องกำหนดกฎตายตัว (ไม่มีการสุ่มหรือ AI) น้ำหนักต่อฟิลด์กำหนดเป็นค่าคงที่ที่ทดสอบได้
- BR-2 ฟิลด์ที่ใช้คำนวณต้องเป็นฟิลด์ atomic ที่มีอยู่จริง (รูป, ราคา/ค่าธรรมเนียม/นโยบายยกเลิกจาก CAM-268, โซน/สิ่งอำนวยความสะดวก) ห้ามอิงฟิลด์ free-text ที่ตีความไม่ได้แน่นอน

## Data

- อ่าน CampSite และฟิลด์ที่เกี่ยวข้อง (รูป, ราคา, ค่าธรรมเนียม, นโยบายยกเลิกจาก CAM-268, สิ่งอำนวยความสะดวก) ไม่เพิ่ม field ใหม่ในโมเดลหลัก อาจเพิ่มค่าคงที่น้ำหนักคะแนนเท่านั้น ไม่มี migration ข้อมูลผู้ใช้
- Depends on: CAM-268 (PREP-2 ฟิลด์ราคา/ค่าธรรมเนียม/นโยบายยกเลิก) ถ้ายังไม่เสร็จ ให้ข้ามฟิลด์นั้นชั่วคราวและระบุในรายการที่ขาดว่า `รอฟีเจอร์นโยบายยกเลิก` (ไม่บล็อกการคำนวณคะแนนพื้นฐาน)

## Out of scope

- หน้าจอ/การ์ดแสดงคะแนนบนแดชบอร์ด → สตอรี่ถัดไป "การ์ดเช็กลิสต์ข้อมูลที่ยังขาด"
- ใช้คะแนนนี้เป็นเกณฑ์บล็อกการเผยแพร่ลาน (publish gate) → ยังไม่ scope รอบนี้
